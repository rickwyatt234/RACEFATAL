# Career shop

## Build the screen

1. Pull this branch and let Unity finish compiling.
2. Run **RACE//FATAL > Career > Build Shop UI** outside Play Mode.
3. The tool opens and saves `Assets/Game/Scenes/01_Career.unity`, replaces the original shop placeholder / generated shop panels, and wires `CareerController.shopView` automatically. Existing race and garage screens remain intact. Rerunning rebuilds the generated shop panels; keep custom additions outside `ShopUI` and `ShopConfirmation`.
4. Start from `00_Bootstrap`, load a campaign, and open **SHOP**.

Use the existing Career Hub builder only if the base scene is missing; that tool recreates the hub. Run the screen builders again after rebuilding the whole hub.

## Behavior

- Stock uses registered GameDatabase engine, chassis and equipment definitions. Categories are generated from available content. Prices and research requirements come from existing definition assets.
- Current prototype assets have `creditCost: 0`; they will be free until prices are set on the definition assets. The shop does not introduce arbitrary balance values.
- Select any item to see its details, price, total owned count (including installed/destroyed instances), and purchase eligibility. Locked and unaffordable items remain inspectable.
- Buy opens a confirmation showing the cost and remaining credits. Confirmation checks current funds, technology, session and price again. Each confirmation buys one uniquely identified component into owned garage inventory. Repeated clicks on the same confirmation cannot create extra purchases.
- Open Garage to install purchased components using the existing garage workflow.
- Use **SAVE CAMPAIGN** to persist purchases, just as the garage uses an explicit save action. Save failures are reported and leave the in-memory purchase available for a save retry. Save and Return / race launch also use the existing campaign save path.
- Whole bikes are excluded because BikeDefinition has no shop price or technology requirement. Selling, buyback and rotating stock are not implemented.

## Validation

Run **RACE//FATAL > Career > Validate Shop Purchases** for domain checks. This can also run with Unity's `-executeMethod CareerShopValidation.Run`. Checks cover all three item kinds, rejected/locked purchases, insufficient funds, exact balance, unique duplicate instances, and zero/negative prices.

In Unity, check:

1. Build twice: exactly one ShopUI and one ShopConfirmation; existing garage/races remain wired.
2. Open a loaded campaign; browse categories and inspect locked/expensive items.
3. Buy then cancel: credits/inventory unchanged. Confirm a purchase: exact debit, owned count increases once. Keyboard/controller navigation stays within the confirmation while open.
4. Open Garage: item appears and can be installed into a compatible empty slot.
5. Save, return to menu, reload: credits, purchased inventory and installation persist.
6. Scroll long lists, check empty content, and review the screen at 1920x1080 and another aspect ratio using the hub's CanvasScaler.

The implementation environment did not include Unity; generated scene layout, compilation and Play Mode/save-reload validation must be checked in the Unity Editor. The scene is generated by the tool and is not prebuilt in this change.
